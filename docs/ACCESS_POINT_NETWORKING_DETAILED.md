# 📡 التحليل المعماري لنظام نقطة الوصول (Access Point) - منظور الشبكات

هذا المستند يشرح بالتفصيل كيف يعمل مكون `access_point.py` كنقطة وصل بين البنية التحتية للشبكة (Network Infrastructure) ونظام إدارة البيانات (Backend Server). الشرح مصمم خصيصاً لتوضيح آليات عمل النظام في طبقات الشبكة المختلفة (OSI Model).

---

## 1. المعمارية الهندسية للشبكة (Network Architecture)

يعتمد النظام على تحويل جهاز الحاسب (اللابتوب) إلى **نقطة وصول لاسلكية (Wireless Access Point)** باستخدام خاصية (Mobile Hotspot) في نظام التشغيل. 

*   **دور الجهاز:** يعمل الجهاز كـ **DHCP Server** و **Default Gateway** للأجهزة المتصلة.
*   **نطاق الشبكة (Subnet):** يقوم النظام بإنشاء شبكة محلية معزولة (LAN)، في نظام Windows غالباً ما تكون على النطاق `192.168.137.0/24`.
*   هذا التصميم يضمن أن كافة الأجهزة (هواتف الطلاب) ستأخذ عناوين IP ديناميكية ضمن هذا النطاق المعزول، مما يسهل عملية حصرها ومراقبتها.

---

## 2. الاكتشاف والمراقبة في طبقة الشبكة (Network Layer - L3)

لمعرفة الأجهزة المتصلة فعلياً بالشبكة المحلية، يقوم السكريبت بتنفيذ **عملية مسح دوري للشبكة (Network Scanning)** كل 4 ثوانٍ.

*   **بروتوكول ICMP:** يتم استخدام رسائل (Echo Request / Echo Reply) الخاصة ببروتوكول ICMP (من خلال أمر `ping`).
*   **خوارزمية المسح (Multithreading):** بدلاً من فحص الـ IPs بالتسلسل (مما قد يستغرق وقتاً طويلاً ويسبب تأخيراً في تسجيل الحضور)، يقوم النظام بفتح **50 خيط معالجة (Threads)** متزامن. 
*   **نطاق الفحص:** يتم إرسال طلبات الـ Ping للأجهزة من `192.168.137.2` حتى `192.168.137.254` (تجاهل العنوان `.1` لأنه غالباً يمثل الـ Gateway).
*   **تحديد الاستجابة:** أي جهاز يرد على رسالة الـ ICMP بـ "Reply from" يتم تسجيل عنوان الـ IP الخاص به في قائمة الأجهزة النشطة حالياً.

---

## 3. تحديد الهوية الفيزيائية في طبقة ربط البيانات (Data Link Layer - L2)

عناوين الـ IP تتغير (Dynamic) بسبب الـ DHCP، لذلك لا يمكن الاعتماد عليها لتحديد هوية الطالب. البصمة الفريدة والثابتة لأي جهاز هي عنوان الـ **MAC Address** الموجود في كرت الشبكة (NIC).

*   **بروتوكول ARP:** يستخدم النظام بروتوكول **ARP (Address Resolution Protocol)** لربط عنوان طبقة الشبكة (IP) بعنوان طبقة ربط البيانات (MAC Address).
*   **آلية العمل:** 
    1. بعد أن يكتشف النظام وجود IP نشط عبر الـ Ping.
    2. يقوم بقراءة جدول الـ ARP الخاص بنظام التشغيل المحلي (باستخدام أمر `arp -a`).
    3. يقوم السكريبت بعمل (Parsing) لمخرجات الجدول، ويبحث عن الـ IP المحدد ليقترن به عنوان الـ MAC الفيزيائي ذو الـ 48-bit (بصيغة `XX:XX:XX:XX:XX:XX`).
*   **الأهمية الأمنية:** استخدام الـ MAC Address يمنع تكرار تسجيل الحضور لجهازين مختلفين استخدما نفس الـ IP في أوقات مختلفة.

---

## 4. التواصل مع السيرفر المركزي في طبقة التطبيقات (Application Layer - L7)

بمجرد تحديد الـ MAC Address، يجب إرسال هذه المعلومة إلى خادم النظام المركزي (Backend).

*   **البروتوكول المستخدم:** يتم التواصل عبر بروتوكول **HTTP/REST API** (مكتبة `requests` في بايثون).
*   **تغليف البيانات (JSON Payload):** يتم إرسال الحدث (`eventType`) سواء كان اتصال (device-connected) أو انفصال (device-disconnected)، مع الـ MAC Address، ومعرف القاعة (`apIdentifier`)، والطابع الزمني (Timestamp).
*   **الأمان والمصادقة:** يتم حماية هذا الـ API باستخدام مفتاح سري (`X-API-Key`) في ترويسة الطلب (Headers) لمنع أي طلبات وهمية من خارج النظام.

### ميكانيكية النبض (Heartbeat Mechanism)
الأنظمة الموزعة (Distributed Systems) تحتاج إلى معرفة حالة العقد (Nodes). 
*   يقوم السكريبت بإرسال رسالة "نبض" (Heartbeat) كل 60 ثانية للسيرفر المركزي.
*   هذا يؤكد للسيرفر أن نقطة الوصول (`AP_101` مثلاً) تعمل بشكل سليم (Online)، وإذا توقف النبض، يعلم السيرفر أن نقطة الوصول فيها عطل (Offline).

---

## 5. إدارة حالة الأجهزة (State Machine & Fault Tolerance)

الشبكات اللاسلكية (Wi-Fi) غير مستقرة بطبيعتها (Packet Loss, Sleep Mode in Smartphones). لذلك يطبق النظام ميكانيكية "تسامح مع الأخطاء" (Fault Tolerance) لمنع تسجيل خروج الطالب لمجرد ضعف بسيط في الإشارة.

1.  **حالة الانضمام (Joined):**
    *   عندما يظهر IP جديد لم يكن موجوداً في الذاكرة المؤقتة (Tracker)، يتم سحب الـ MAC Address الخاص به وإرسال حدث `device-connected` للسيرفر.
2.  **حالة الاستقرار (Active):**
    *   طالما أن الجهاز يرد على الـ Ping، فإن عداد الفقدان (Missed Pings) يتم تصفيره.
3.  **حالة الانفصال التدريجي (Tolerance):**
    *   إذا اختفى الجهاز من الفحص (لم يرد على الـ Ping)، **لا يتم إخراجه فوراً**. بل يزداد عداد (Missed) بمقدار 1.
    *   الحد الأقصى للتسامح هو `MAX_MISSED_PINGS = 30`. نظراً لأن الفحص يتم كل 4 ثوانٍ، فهذا يعطي الجهاز فترة سماح تبلغ حوالي (120 ثانية / دقيقتين) قبل اعتباره مفصولاً فعلياً.
4.  **حالة المغادرة (Left):**
    *   بمجرد تجاوز الجهاز لحد التسامح، يتم حساب مدة بقائه الكلية، ويُرسل حدث `device-disconnected` للسيرفر، ويُحذف الجهاز من الذاكرة المؤقتة.

---

## 6. دورة سير البيانات المتكاملة (End-to-End Workflow)

1.  **تأسيس الشبكة:** الطالب يدخل القاعة ويقوم بتفعيل الـ Wi-Fi والاتصال بنقطة اتصال اللابتوب (Mobile Hotspot). اللابتوب يعطيه IP (عبر DHCP).
2.  **اكتشاف الطبقة الثالثة (L3):** سكريبت بايثون يرسل ICMP Ping بشكل متوازي لكل النطاق، وجوال الطالب يرد (Echo Reply).
3.  **ربط الطبقة الثانية (L2):** السكريبت يقرأ جدول الـ ARP لمعرفة الـ MAC Address المقابل لـ IP الطالب.
4.  **تحديث الحالة:** السكريبت يسجل الجهاز في ذاكرته، ويقوم بإعداد طلب HTTP POST (طبقة التطبيقات L7).
5.  **المزامنة مع السيرفر:** يُرسل الـ MAC ومعرف القاعة إلى الـ Backend API.
6.  **قاعدة البيانات:** السيرفر يستقبل الـ MAC، يبحث في قاعدة بيانات الطلاب، إذا وجد تطابق، يُسجل الطالب "حاضر" في المحاضرة المفتوحة حالياً في هذه القاعة.
